## Added

**Pre-deploy hooks.** Run a shell or argv command from the resolved image
before it replaces the current container. Hooks receive the effective app
environment and network, report their phase and output, and leave the old
version serving when they fail, time out, or are cancelled.

**Deployment identity.** Every app and pre-deploy container receives reserved
`CUBESHIP_` variables describing its project, environment, app, deployment,
replica, and node. Git-backed deployments also expose the source branch and
commit that produced them.

**Git path filters.** Configure repository-relative watch and ignore globs so
Git-triggered builds run only when relevant files change. Deployments skipped
because no watched path changed are recorded, while incomplete webhook file
data fails open so a change is not silently missed.

**Dockerfile build arguments.** Store validated, allowlisted build arguments
separately from runtime environment variables and pass them only to Dockerfile
builds. Reserved `CUBESHIP_` names and invalid keys are rejected, and values
are not returned by default because image history, layers, and cache may retain
them.

## Changed

**Deploy validation and replacement safety.** Configured HTTP or TCP health
checks remain the gate before traffic moves, and pre-deploy hooks run before
that swap. Apps can now choose their stop signal and grace period, and the
policy is honored during deploy retirement, pause, worker replacement, and
volume operations.

**Dashboard controls.** App settings expose stop-policy fields, build-argument
editing, rebuild actions, and warnings about build-argument persistence. The
Bitbucket provider page now includes its OAuth and webhook configuration and
the required callback URLs.

## Upgrade notes

Update normally from the dashboard or CLI. The pre-deploy, stop-policy,
path-filter, deployment-identity, and build-argument migrations apply
automatically on daemon startup.
