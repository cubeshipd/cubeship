## Added

**GHCR package scope.** Registry pages list packages owned by the authenticated user and organizations their credential can access. Build image selectors preload accessible repositories and tags; public images can still be selected by entering their exact image name. Search no longer means filtering a truncated global GHCR listing. Git repositories and branches are also preloaded when entering Build, and Docker image data is warmed when opening an app that uses an image.

**App networking and readiness.** Networking settings let an app declare its internal container ports and multiple HTTP health checks, each with a path, port, initial delay, period, timeout and success/failure thresholds. Every configured check must reach its success threshold before a new container is considered ready; reaching a check's failure threshold fails that deployment. `PUT /apps/{project}/{env}/{name}/networking` and the `configure_app_networking` MCP tool expose the settings. Traefik uses the first configured check for ongoing service monitoring. Declared internal ports appear in Overview, and domain routes without an explicit port use the app's only declared internal port when there is one.

**Named template installations.** Installation Name is a prefix applied to resources the template creates, and is shown as the installed template's identity. Older installed templates without a name ask for one when opened; naming them does not rename existing resources.


## Upgrade notes

The daemon applies migrations automatically. Existing app domain and TCP ports are carried into internal port declarations, and legacy health paths become health checks with their existing effective port (or port 8080 when none was configured). Existing template installations keep their resources; opening an unnamed installation requires assigning its display name once.
