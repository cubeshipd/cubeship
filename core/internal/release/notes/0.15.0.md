## Added

**A deploy webhook for every app.** Every app has a URL that deploys it when
something posts to it, so a CI that pushes to GHCR or Docker Hub can ask for
a deploy without an API key. The token in the URL is the authorization.
`?tag=1.2.3` deploys that tag and, on an external app or a registry app
pinned to a tag, saves it, so later deploys stay on it. `?ref=` deploys a
branch, tag or commit of an app that builds, for that deploy only.
`?wait=true` answers when the deploy ends, waiting at most 15 minutes. A
parameter the webhook does not take is refused with `400`, and a body is
ignored, so any sender can post its own payload. Each call is in the audit
log, never with its token.

The URL is on the app's Build tab under **Deploy webhook**, with
`cubeship app hook <app>` and through the `get_app_deploy_hook` MCP tool.
Only someone who can deploy the app sees it: a member for an app that runs
an image, an admin for one that builds. **Regenerate**,
`cubeship app hook rotate <app> --yes` and `rotate_app_deploy_hook` give it a
new token and the old URL stops working. Changing an app to a source that
builds regenerates it too.

**Public images from any registry.** The image registry choice adds
**Public image (any registry)**, for an image on GHCR, Quay, GitLab, ECR
Public or anywhere else with nothing connected; the pull and the tag list
are anonymous. Typing a reference that names another registry moves the
choice to it and keeps what was typed.

## Fixed

**Tags of a public image list when the stored login is refused.** The tag
list now tries again without the login, instead of showing nothing.

## Upgrade notes

Stable installs and automatic stable updates now use 0.15.0. The daemon
applies migrations when it starts, and every existing app gets its own
deploy token. Nothing else needs configuring.
