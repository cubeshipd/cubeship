## Fixed

**Deployment readiness on the control plane.** HTTP and TCP probes now run
from a restricted, temporary helper in the candidate app's network namespace.
Apps that answer their health path can pass readiness while the daemon stays
on its private management network. App images need no shell or probe tools.
HTTP readiness requires a direct 2xx response; redirects do not count as success.

**Readiness failures and cancellation.** Failed deployments include the last
probe error. Canceling a readiness check removes its helper and the candidate
container, preserving the serving version. For deployments that stop the old
container first, cancellation restarts that previous version.

**MCP pre-deploy commands.** The create_app and update_app tools accept a shell
string or an array of strings, and app responses return those values without
schema validation errors. Omitting the command preserves it; an empty string,
an empty array, or null clears it. Updating the command preserves its timeout
unless a new timeout is supplied.

## Changed

**Health-check documentation.** The docs now describe the control-plane deploy
readiness gate, HTTP and TCP port selection, retries, cancellation, and the
difference between deployment checks and ongoing proxy checks.

## Upgrade notes

Select 0.12.0-rc.7 from an instance with prereleases enabled, or name this version
when installing. No new database migrations are added after rc.6. Existing app
health paths and pre-deploy commands are retained. This candidate does not move
the stable latest release or image tags.
